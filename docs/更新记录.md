## 2026-08-03 · 修复东财 PDF 下载 + 扩资讯源

### 根因

`https://pdf.dfcfw.com/pdf/H3_{infoCode}_1.pdf` 在服务端常返回 **JS 挑战页**（仍标 `Content-Type: application/pdf`，正文是 `<script>`）。浏览器可过，httpx 不行。同路径 **`http://` 可直下真实 PDF**。链接模板本身正确。

### 修复

- PDF 下载优先 `http://`，校验 `%PDF` 魔数
- 策略/宏观/晨报改走 `/report/jg`，并从详情页解析真实 `AP…` infoCode
- 默认 qType 含个股 `0`

### 新源

- `eastmoney_news`：东财资讯栏目（导读/股市/公司/宏观）
- 配置：`REPORT_COLLECTOR_SOURCES=eastmoney_report,eastmoney_news`

### API

`POST /api/v1/reports/{id}/refetch-pdf` — 对已入库 incomplete 条目重抓 PDF

## 2026-08-03 · 资讯自动摘要（非因子）+ 提示词「资讯分析」分类

### 摘要

资讯入库后自动入队 **LLM 摘要/要点提取**（不走因子流水线）。提示词管理新增分类 **资讯分析**（`news_summarize`）。

### 行为

- 采集 / 上传 / 粘贴入库 → `enqueue_news_summarize`
- 结果写入 `report.meta`：`news_summary_status` / `news_summary` / `news_summary_error`
- 前端「原文」抽屉展示摘要；可「重新摘要」
- 因子按钮仍为可选人工发起

### 配置

`NEWS_SUMMARIZE_ENABLED`（默认 true）、`NEWS_SUMMARIZE_MAX_CHARS`、`NEWS_SUMMARIZE_WORKERS`

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/reports/{id}/summarize` | 手动/重跑摘要 |
| GET | `/api/v1/reports/{id}/content` | 含 `news_summary*` |

### 提示词

`prompts/news_summarize.json` · UI 分组「资讯分析」

## 2026-08-03 · 产品分层：因子层保留，策略层后续独立建设

### 摘要

明确 **不改造** 现有单因子评估主链路。业界「多因子组成策略」属于其上的组合层；单因子六角色门禁仍是必要前置（Factor Research）。

### 产品边界

| 层级 | 状态 | 职责 |
|------|------|------|
| **因子层**（现有） | 已实现、保持不变 | 研报提取 / 库优化 → 六角色单因子评审 → SAVE/REVISE/DROP → 任务入库 / 淘汰库 |
| **策略层**（规划） | 未实现，见专题设计 | 从任务入库勾选多因子 → 合成规则 → 策略级评估 → 策略库 |

### 为何不把策略塞进现有 Step2/门禁

- 角色职责会从「评公式」变成「评组合」，提示词与回灌修订语义混乱
- 单因子质量问题应独立 DROP/修订，不应因组包失败牵连整池
- Alpha101 / 任务入库 / 淘汰库的单条优化闭环需继续可用

### 本期动作

- **零代码改主流程**（`decide_action`、LangGraph 节点职责不变）
- 文档写清分层；策略 MVP 实现计划见 [多因子策略层设计](./多因子策略层设计.md)

## 2026-07-31 · 因子库三分区与任务落库

### 摘要

因子库从「只读 Alpha101 + 临时任务汇总」升级为三库结构；任务落盘时自动写入过线 / 淘汰结果。

### 功能

| 分区 | pack_id | 数据文件 | 内容 |
|------|---------|----------|------|
| Alpha101 | `alpha101` | `data/factor_library/alpha101.json` | 公开公式库（只读） |
| 任务入库 | `workspace` | `data/factor_library/workspace.json` | 门禁 **SAVE** 因子 |
| 淘汰库 | `dropped` | `data/factor_library/dropped.json` | 门禁 **DROP** 因子（含公式与淘汰原因） |

- 前端「因子库」三 Tab：Alpha101 / 任务入库 / 淘汰库；均可勾选「优化因子」
- 任务详情「因子公式」同时展示 SAVE 与淘汰因子（`GET .../factors?include_candidates=true`，默认开启）
- 优化入口覆盖：Alpha101、任务入库、淘汰库

### 流水线相关

- `persist`：SAVE → `workspace`；有公式的 DROP → `dropped`
- 修订轮：每轮最多修订 5 个最低分因子；Step1 上下文瘦身；LLM 硬超时
- 取消/超时可打断长时间 LLM 调用（去掉 `asyncio.shield` 阻挡）
- 支持 `POST /api/v1/jobs/{id}/rerun` 再次分析

### API

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/factor-library/packs` | 含 alpha101 / workspace / dropped |
| GET | `/api/v1/factor-library/{pack_id}/factors` | 分页搜索；`dropped` 含 `reason` |
| GET | `/api/v1/jobs/{id}/factors` | SAVE + 可选淘汰因子 |
| POST | `/api/v1/jobs` | `mode=evaluate` 优化评估 |
| POST | `/api/v1/jobs/{id}/rerun` | 再次分析 |

### 实现索引

| 模块 | 路径 |
|------|------|
| 因子库服务 | `backend/factor_backend/services/factor_library.py` |
| 落盘节点 | `backend/factor_backend/graph/nodes.py` → `node_persist` |
| 因子库 API | `backend/factor_backend/api/routes_factor_library.py` |
| 因子库页 | `frontend/src/views/FactorsView.vue` |
