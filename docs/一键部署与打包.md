# 一键部署与打包方案

## 1. 为什么服务器会“配置复杂”

本项目不是单脚本，而是：

- 提示词包（`prompts/`）
- 编排引擎（LangGraph / Python）
- LLM API Key / 模型路由
- 行情 MCP（后续独立服务）
- 可选：数据库、对象存储、队列

若在服务器上手动装 Python、依赖、配环境变量、起多个进程，很容易碎。目标改成：**拷贝目录 → 填密钥 → 一条命令启动**。

## 2. 方案对比

| 方案 | 一键程度 | 复杂度 | 推荐场景 |
|------|----------|--------|----------|
| **Docker Compose（推荐）** | `compose up -d` | 低 | 公司服务器 / 内网机 |
| **安装脚本 + Compose** | `./scripts/bootstrap.sh` | 更低（自动检查 Docker） | 给运维/同事交付 |
| **离线镜像包** | `load + up` | 中 | 无外网机房 |
| **纯 pip + systemd** | 多步 | 高 | 禁止 Docker 的环境 |
| **K8s/Helm** | 中 | 高 | 已有集群再上 |

**默认选型：Docker Compose 打进仓库；外层再包一层 bootstrap 脚本。**

## 3. 一键体验（目标）

```bash
# 有 Docker 的机器上
cp .env.example .env          # 只改 LLM_API_KEY 等
./scripts/bootstrap.sh        # Linux/macOS
# 或
./scripts/bootstrap.ps1       # Windows

# 等价手动
docker compose up -d --build
```

启动后：

- API：`http://localhost:8080`
- 健康检查：`GET /health`
- 提示词与配置已打进镜像/挂载卷，无需再装 Python 依赖

## 4. 容器拓扑

```text
┌──────────────────────────────────────────────┐
│ docker compose                               │
│                                              │
│  ┌─────────────┐    ┌─────────────────────┐  │
│  │ factor-api  │───▶│ LLM Provider        │  │
│  │ (编排+提示词)│    │ (外网或内网网关)     │  │
│  └──────┬──────┘    └─────────────────────┘  │
│         │                                    │
│         ├────▶ market-mcp (可选 profile)     │
│         │      K线/成交量…                   │
│         │                                    │
│         └────▶ redis (可选，状态/队列)        │
└──────────────────────────────────────────────┘
```

- **最小模式**：只起 `factor-api`（MCP 未就绪时 Agent 返回 `data_unavailable`）
- **完整模式**：`docker compose --profile full up -d`（含 mcp + redis）

## 5. 配置分层（避免改代码）

| 层级 | 文件 | 内容 |
|------|------|------|
| 密钥 | `.env` | API Key、端口、开关（不进 Git） |
| 业务默认 | `config/default.yaml` | max_round、门槛、模型名 |
| 提示词 | `prompts/*.json` | Agent 提示词，随镜像或挂载 |
| 运行覆盖 | 环境变量 / `config/local.yaml` | 机房差异 |

原则：**换模型、改门槛、开关 MCP = 改配置重启，不改代码。**

## 6. 服务器交付清单

交付物可以是 Git 仓库，或打包 zip：

```text
factor-agent-bundle/
├── docker-compose.yml
├── Dockerfile
├── .env.example
├── config/default.yaml
├── prompts/
├── app/
├── scripts/bootstrap.sh
├── scripts/bootstrap.ps1
└── docs/
```

内网离线：

```bash
# 有网机构建并导出
docker compose build
docker save factor-api:latest | gzip > factor-api.tar.gz

# 无网机
gunzip -c factor-api.tar.gz | docker load
cp .env.example .env   # 填内网 LLM 网关
docker compose up -d
```

## 7. 不推荐的做法

- 在服务器 `pip install` 一堆包且无锁定版本  
- 把 API Key 写进镜像  
- 让运维手工改 6 个角色提示词路径  
- Step3 算分放远程“智能体”里心算（应用代码节点，已在设计中）
