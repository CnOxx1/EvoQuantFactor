# 资讯分析与采集

> 多源资讯/研报入库 → LLM **资讯摘要**（非因子）→ 可选人工发起因子流水线。  
> 本页是资讯模块的专题说明；API 速查见 [API-前端对接](API-前端对接.md)，变更见 [更新记录](更新记录.md)。

| 项 | 路径 |
|----|------|
| 前端页 | `/reports` → `frontend/src/views/ReportsView.vue` |
| 采集器 | `backend/factor_backend/services/report_ingest/collector.py` |
| 适配器 | `backend/factor_backend/services/report_ingest/*.py` |
| 指纹/标题 | `report_ingest/fingerprint.py` |
| 摘要队列 | `backend/factor_backend/services/news_summarize.py` |
| HTTP | `backend/factor_backend/api/routes_reports.py` |
| 提示词 | `prompts/news_summarize.json`（分类 **资讯分析**） |
| 配置 | `factor_backend/config.py` / 根目录 `.env.example` |

本地默认：后端 `18081`，前端 `5174`。

---

## 1. 定位与边界

| 做 | 不做 |
|----|------|
| 多源定时/手动采集入库 | **不**自动创建因子 Job |
| 入库后 LLM 结构化摘要 | **不**从资讯抽量化公式（提示词明确禁止） |
| 查看原文 + 摘要；坏标题/PDF 修复 | 策略层组合（另见 archive/多因子策略层设计） |
| 人工点「因子」才进 LangGraph | — |

与因子层关系：资讯页的「因子」按钮 → `POST /api/v1/jobs`（`mode=extract`），之后走现有提取/评审流水线。宏观/晨报/正文不完整会二次确认，但不拦截入库与摘要。

## 2. 端到端流程

```text
启动后端
  ├─ start_report_collector()     # 可选：定时采集线程
  └─ start_news_summarize_workers()  # 摘要 worker 池

采集一轮（定时 / POST collect/run）
  ├─（可选）坏标题回填
  ├─ 按 REPORT_COLLECTOR_SOURCES 串行拉各源
  ├─ external_id 去重 → content_fp 跨源去重 → save_report
  ├─ enqueue_news_summarize(report_id)
  └─（可选）自动重抓 incomplete 东财 PDF

摘要 worker
  └─ LLM(news_summarize) → 写入 meta.news_summary*

前端 /reports
  ├─ 列表 / 筛选（采集状态见顶栏通知）
  ├─ 原文抽屉（摘要 + 正文 + 重抓 PDF / 重新摘要）
  └─「因子」→ 创建 Job（人工）
```

人工入库同样会入队摘要：

- `POST /api/v1/reports`（文件）
- `POST /api/v1/reports/text`（纯文本）

## 3. 代码与数据

### 3.1 适配器一览

| 配置 key（SOURCES） | 入库 `source` 字段 | 文件 | 登录 | 说明 |
|---------------------|-------------------|------|------|------|
| `eastmoney_report`（别名 `eastmoney`） | `eastmoney` | `eastmoney.py` | 否 | 研报列表 + PDF 抽文本 |
| `eastmoney_news` | `eastmoney_news` | `eastmoney_news.py` | 否 | 栏目新闻 HTML |
| `wallstreetcn`（`wscn`） | `wallstreetcn` | `wallstreetcn.py` | 否 | 7x24 + 文章 |
| `sina`（`sina_finance`） | `sina` | `sina_finance.py` | 否 | 滚动资讯（多为列表摘要） |
| `ths`（`10jqka`） | `ths` | `ths_news.py` | 否 | 快讯（多为列表摘要） |
| `jin10` | `jin10` | `jin10.py` | 否 | `flash_newest.js`；标题取 `data.title` / 正文首句 |
| `luobo`（`datayes`/`robo`） | `luobo` | `luobo.py` | **是** | 资讯流 + 研报；需 token |
| — | `upload` / `text` | 上传接口 | — | 人工入库 |

默认 `REPORT_COLLECTOR_SOURCES`（其余源仍保留适配器，需显式加入）：

```text
eastmoney_report,eastmoney_news
```

> **默认关闭**：`REPORT_COLLECTOR_ENABLED=false`、`NEWS_SUMMARIZE_ENABLED=false`，避免拖垮 API 进程。需要时再打开，或用 `python -m factor_backend collector` / `summarize` 独立进程。

### 3.2 入库记录主要字段

**表/行级：** `report_id`、`title`、`filename`、`content`、`source`、`external_id`、`created_at`、`meta_json`

**`meta` 常见键：**

| 键 | 含义 |
|----|------|
| `source` / `external_id` | 来源与跨次去重 ID（如 `jin10:…`、`eastmoney:AP…`） |
| `content_fp` | 跨源近似指纹（标题前缀 + 正文前缀） |
| `q_type` / `q_type_label` | 东财研报类型（0 个股 / 1 行业 / 2 策略 / 3 宏观 / 4 晨报） |
| `org` / `author` / `publish_date` | 机构、作者、日期 |
| `pdf_url` / `info_code` / `pdf_bytes` | 东财 PDF |
| `text_incomplete` / `pdf_error` | 正文不完整或 PDF 失败 |
| `news_summary_status` | 摘要状态（见下） |
| `news_summary` | 摘要 JSON 对象 |
| `news_summary_error` | 失败/队列满等原因 |
| `news_summary_updated_at` / `news_summary_at` | 时间戳 |
| `title_backfilled_at` | 坏标题被回填的时间 |

### 3.3 摘要状态 `news_summary_status`

| 值 | 含义 | 前端展示 |
|----|------|----------|
| （空） | 未入队 | 未摘要 |
| `pending` | 已入队或队列满占位 | 排队中 |
| `running` | 正在调用 LLM | 生成中 |
| `done` | 成功，见 `news_summary` | 已完成 |
| `failed` | 失败，见 `news_summary_error` | 失败 |
| `skipped` | 如 `NEWS_SUMMARIZE_ENABLED=false` | 已跳过 |

**注意：** 队列满时也会写成 `pending`，错误形如 `queue_full>200`；当前不会自动在腾出容量后重入队，需「补跑未摘要」或 `summarize/backfill`。

### 3.4 摘要 JSON 结构（`news_summary`）

与提示词 schema 一致：

| 字段 | 说明 |
|------|------|
| `headline` | 一句话标题级摘要 |
| `summary` | 150–400 字摘要 |
| `key_points` | 要点列表 |
| `entities` / `topics` | 主体 / 主题标签 |
| `sentiment` | 偏多\|中性\|偏空\|不明 |
| `time_sensitivity` | 高\|中\|低\|不明 |
| `implications` | 可选推断（非投资建议） |
| `quality_note` | 正文完整性等说明 |

## 4. 采集行为详解

### 4.1 定时与手动

| 方式 | 说明 |
|------|------|
| 定时 | `REPORT_COLLECTOR_ENABLED=true` 时后台线程；间隔 `REPORT_COLLECTOR_INTERVAL_SEC`（**最小按 60s 钳制**） |
| 手动 | 前端「立即同步」或 `POST /api/v1/reports/collect/run`（同步阻塞，多源可能较久） |
| 启动 | `main.py` lifespan 调用 `start_report_collector()` |

轮次内大致顺序：标题回填（可选）→ 各源采集 → 自动 PDF 重抓（可选）→ 写 `source_stats`。

### 4.2 去重

1. **`external_id`**：同 ID 已存在则跳过（`skipped`）  
2. **`content_fp`**：`REPORT_COLLECTOR_FINGERPRINT_DEDUPE=true` 时，标题+正文规范化前缀的 SHA1 前 16 位；本轮内存 + DB `meta_json` 检索。过短正文可能算不出指纹。

### 4.3 东财研报 / PDF

- 个股/行业：列表接口；策略/宏观/晨报：`/jg` 再解析真实 `AP…` infoCode  
- PDF 优先 `http://pdf.dfcfw.com/pdf/H3_{infoCode}_1.pdf`（`https` 易返回 JS 挑战页，非真正 PDF）  
- 失败时用标题/摘要占位，并标 `text_incomplete`  
- **手动重抓：** `POST /api/v1/reports/{id}/refetch-pdf`  
- **自动重抓：** 每轮最多 `REPORT_COLLECTOR_PDF_REFETCH_LIMIT` 条（`0` 关闭）  
- 东财 `q_types`：`REPORT_COLLECTOR_QTYPES`（默认 `0,1,2,3`）  
- 资讯栏目：`REPORT_COLLECTOR_NEWS_COLUMNS`（默认导读/股市/公司/宏观/产经/国际）

### 4.4 萝卜投研

1. 浏览器登录 https://robo.datayes.com  
2. Cookie 中 `cloud-sso-token` → `.env` 的 `LUOBO_CLOUD_SSO_TOKEN`（或整段 `LUOBO_COOKIE`）  
3. 重启后端  
4. `luobo_configured` / `luobo_auth_required`；前端黄条提示  
5. `LUOBO_COLLECT_FEEDS` / `LUOBO_COLLECT_REPORTS` 控制是否采资讯流/研报  

未配置时该源计失败/鉴权错误，**其它源继续**。

### 4.5 坏标题回填

识别规则（`fingerprint.is_bad_title`）包括：空标题、等于 `external_id`、`jin10:…` 等形式、`金十快讯 + 纯数字` 等。

| 触发 | 说明 |
|------|------|
| 启动采集线程时 | `REPORT_COLLECTOR_TITLE_BACKFILL_ON_START=true` |
| 每轮采集开始 | 同上，小批量 |
| API / 前端 | `POST /titles/backfill`、「修复坏标题」 |

从正文「标题：」行或正文首句重写；若正文本身也是占位则无法修复。

### 4.6 `collect/status` 字段

| 字段 | 说明 |
|------|------|
| `enabled` / `running` | 是否开启定时 / 本轮是否在跑 |
| `last_*` | 起止时间、新增、跳过、错误列表 |
| `total_runs` / `last_sources` | 累计轮次、本轮源 |
| `luobo_configured` / `luobo_auth_required` | 萝卜登录态 |
| `source_stats` | 每源：`added` / `skipped` / `dup_fp` / `failed` / `elapsed_ms` / `auth_error` |
| `pdf_refetched` / `titles_fixed` / `fingerprint_skipped` | 本轮附属统计 |
| `summarize` | 嵌套摘要队列状态（同 `summarize/status`） |

## 5. 摘要队列

| 配置 | 默认 | 说明 |
|------|------|------|
| `NEWS_SUMMARIZE_ENABLED` | `false` | 总开关（默认关） |
| `NEWS_SUMMARIZE_WORKERS` | `2` | 并行摘要路数（每路一次 LLM/Cursor agent） |
| `NEWS_SUMMARIZE_WORKERS_CAP` | `32` | 安全上限；运行中可向上扩容，缩容需重启 |
| `NEWS_SUMMARIZE_QUEUE_MAX` | `500` | 队列上限；满则丢弃并记 `dropped_full` |
| `NEWS_SUMMARIZE_MAX_RETRIES` | `2` | 单条失败重试 |
| `NEWS_SUMMARIZE_MAX_CHARS` | `24000` | 送入 LLM 的正文截断 |

`summarize/status` 另含 `workers`（存活）、`workers_configured`、`workers_cap`。

- 入队去重：同一 `report_id` 已在 pending 集合则跳过  
- 状态：`GET /api/v1/reports/summarize/status`  
  含 `queue_depth` / `queue_max` / `running` / `enqueued_total` / `dropped_full` / `done_total` / `failed_total` / `retry_total` / `workers` / `last_error`  
- **补跑：** `POST /summarize/backfill?limit=&only_missing=`（默认只处理未 `done`；实现上扫最近 `limit` 条，偏新）  
- 单条重跑：`POST /{id}/summarize?force=true`  
- LLM 未配置时可用 mock 摘要（视全局 LLM 配置）

## 6. 前端「资讯分析」

路径：`/reports`

| 区域 | 能力 |
|------|------|
| 顶栏操作 | 修复坏标题、补跑未摘要、立即同步、刷新 |
| 通知中心 | 采集/萝卜/摘要队列等状态统一在顶栏铃铛（轮询 `collect/status`）；模块页内不重复展示 |
| 筛选 | 关键词、`source`、因子适配 `suitability` |
| 表格 | 标题/机构/类型/摘要状态/来源/日期/因子标签/操作 |
| 抽屉 | 摘要、`quality_note` 相关字段、原文、重抓 PDF、重新摘要、打开源 PDF |
| 因子 | 宏观(`q_type=3`)/晨报(`4`)/`text_incomplete` →「不建议因子」二次确认 |

列表查询参数：`q`、`source`、`suitability=factor|news_only`、`limit`、`offset`。

**因子适配粗筛（服务端 `suitability`）：**

- `factor`：排除宏观、晨报、`text_incomplete`  
- `news_only`：仅上述「不建议因子」类  

快讯源（金十/同花顺/新浪等）目前默认仍算「适合因子」粗筛——产品上可能仍不适合做因子，需人工判断。

通知：同步结果也会进全局通知中心（`notifyCollectorStatus`）。

## 7. API 一览

鉴权：与其它 API 相同（`AUTH_DISABLED=true` 时可免 token）。

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/reports` | 列表；`q` / `source` / `suitability` / `limit` / `offset` |
| GET | `/api/v1/reports/{id}` | 元信息 |
| GET | `/api/v1/reports/{id}/content` | 原文 + `news_summary*` + `text_incomplete` + `pdf_url` |
| POST | `/api/v1/reports` | multipart 上传文件 |
| POST | `/api/v1/reports/text` | JSON 纯文本入库 |
| POST | `/api/v1/reports/collect/run` | 手动采集一轮（耗时可能很长） |
| GET | `/api/v1/reports/collect/status` | 采集 + 嵌套摘要状态 |
| POST | `/api/v1/reports/titles/backfill` | 坏标题回填；`limit` |
| GET | `/api/v1/reports/summarize/status` | 摘要队列 |
| POST | `/api/v1/reports/summarize/backfill` | 批量入队摘要 |
| POST | `/api/v1/reports/{id}/summarize` | 单条摘要；`force` |
| POST | `/api/v1/reports/{id}/refetch-pdf` | 东财 PDF 重抓后重新入队摘要 |
| POST | `/api/v1/jobs` | 基于 `report_id` 创建因子分析（人工） |

## 9. 运维与排障

| 现象 | 排查 |
|------|------|
| 状态条卡住 / 同步不结束 | 确认后端已含「采集结束释放锁再返回 status」的修复；重启 uvicorn |
| 萝卜未配置告警 | 看顶栏通知；更新 `LUOBO_CLOUD_SSO_TOKEN` 后重启 |
| 大量「排队中」且不推进 | 看 `summarize.queue_depth` / `dropped_full`；加大 workers 或补跑；查 LLM 是否可用 |
| 东财正文不完整 | 打开原文看 `pdf_error`；点「重抓 PDF」；http 仍失败则为站点风控 |
| 标题仍是 `jin10:…` | 「修复坏标题」；若正文无有效首句则无法修 |
| 立即同步 HTTP 超时 | 多源串行 + gap，可只保留需要的 `REPORT_COLLECTOR_SOURCES` 或拉长前端 timeout |
| 采集重叠 | 定时与手动可重叠跑；避免连续狂点「立即同步」 |

改代码后需**重启后端**（当前通常不用 `--reload`）。

## 10. 已知限制（规划中）

- 新浪/同花顺/部分见闻多为**列表摘要体**，非全文 HTML；摘要质量受限于入库文本  
- 队列满丢弃后需人工/补跑，无自动 drain  
- `summarize/backfill` 默认只扫最近 N 条，不是全库按状态扫描  
- 指纹存在 `meta_json` 子串匹配，无独立索引列  
- 因子适配粗筛未把快讯源默认标成 `news_only`  
- PDF 重抓成功后若抽字过短，完整度标记仍可能偏乐观  
- 采集 `POST /collect/run` 同步阻塞，无独立任务 ID
